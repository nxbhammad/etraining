How it ships in Moodle 4.3.5 + IOMAD

Phase 1 can go out with the kit’s own files. Phase 2 is where the failure rate actually drops.

Phase 1 · settings and template

No PHP · this week

  • Turn on “Allow log in via email” after checking for shared emails.
  • Support name and email fixed, as in the kit.
  • New loginform.mustache: one identifier field, company header, Show/Hide, 52 px targets.
  • Longer session plus a persistent-login plugin for “Stay signed in on this device.”

Phase 2 · code sign-in plugin

One auth plugin · 3–4 weeks

  • Resolve identifier: username, email, or mobile (IOMAD profile field).
  • 6-digit code by SMS (Twilio or AWS SNS) or email, 10-minute life, one use.
  • Manager access code: 8 characters, 24 hours, created from the IOMAD company user list.
  • Rate limits per account and per IP. Codes never shown in logs.

Phase 3 · passkeys

After phase 2 is stable

  • “Use fingerprint or face next time” on the welcome screen.
  • WebAuthn on the same plugin; falls back to a code on a new device.
  • Company SSO (Microsoft / Google) per portal where the company has it.
